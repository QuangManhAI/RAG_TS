06 · Đặc tả Chức năng AI, Dữ liệu sử dụng & Cấu trúc Output

Tác vụ AI & Dữ liệu sử dụng

09 · Thiết kế RESTful API theo 8 nguyên tắc

Tái cấu trúc từ 8 route động từ thành 34 routes chuẩn /api/v1, khóa khớp hợp đồng bằng test API contract (OpenAPI).

Nguyên tắcÁp dụng thực tế trong RAG_TS [S2][S27]
1. Danh từ cho URL/auth/login, /auth/register, /admin/users/:id/disable → /auth/tokens, /users, /admin/users/:id/status (0/34 động từ).
2. HTTP Method & IdempotencyPUT thay toàn bộ (roles, status, password); PATCH sửa một phần (/users/me, /chat-sessions/:id). PUT/DELETE không đổi state → không ghi DB/audit; POST /rag/chat* dùng Idempotency-Key; riêng token-rotations cố ý không idempotent.
3. Status CodesChuẩn 200/201/204, 400/401/403, 404 (thay 403 cho session người khác chống IDOR), 405 (+ Allow), 406, 409, 415, 429, 503/504.
4. VersioningGắn trên path /api/v1 (VITE_API_BASE=/api/v1); breaking change mới lên /api/v2.
5. Đa định dạngĐàm phán Content-Type & Accept cho JSON và XML (kể cả error envelope); chặn DOCTYPE/ENTITY XXE max 100 KB.
6. Naming & HATEOASDanh từ số nhiều kebab-case, field snake_case; điểm vào GET /api/v1 và _links trên 26/34 routes.
7. Batch ProcessingGET /papers?ids=a,b (max 20), GET /chat-sessions?ids=, DELETE /chat-sessions?ids= giảm N+1 calls.
8. Query LanguageThống nhất limit + cursor (thay page/size để tránh trùng/sót dòng khi chat tăng), sort=field:asc|desc, filter (eq,ne,gt,gte,lt,lte,match), ?q=.

10 · Quy trình xử lý Request & Response trong Backend

Mọi request qua đúng một chuỗi middleware, guard, pipe, interceptor và filter trong configureApp() (dùng chung cho cả prod & E2E).

1. Middleware & Bảo mậttrust proxy · X-Request-Id · helmet · Prometheus
2. Body Check (100KB)415 unsupported · XML XXE parser
3. Guards & PipeThrottler · JWT/Roles · ValidationPipe
4. Interceptors (Out)LinksInterceptor → ContentNegotiation

Inbound Request Processing [S19]

  • Tầng Express đầu vào: express.set('trust proxy') đọc TRUST_PROXY_HOPS → requestIdMiddleware gắn X-Request-Id → helmet CSP/HSTS → PrometheusMetricsRegistry [S19].
  • Kiểm tra Content-Type: Từ chối 415 nếu khác JSON/XML; nếu XML thì parse qua textBody(100kb) + xmlBodyMiddleware chặn DOCTYPE/ENTITY [S2][S19].
  • Guards & Validation: ThrottlerGuard toàn cục (120/m + @RateLimit riêng) → JwtAuthGuard / RolesGuard → ValidationPipe (whitelist + forbidNonWhitelisted + transform) [S18][S19].

Outbound Response & Error Handling [S2][S3][S19]

  • Controller / Stream: Routes REST trả DTO thường; POST /rag/chat/stream qua ClientSlots (2/user, 3/IP) rồi stream SSE qua SseWriter (: ping 15s) [S3].
  • Thứ tự Interceptors (vòng ngoài bọc vòng trong): LinksInterceptor gắn HATEOAS _links trước, sau đó ContentNegotiationInterceptor serialize JSON hoặc XML theo header Accept (trả 406 nếu không hỗ trợ) [S2][S19].
  • Global HttpExceptionFilter: Chuẩn hóa body { statusCode, error, message, details, timestamp, path, request_id }, tự sinh header Allow cho lỗi 405, ghi 1 dòng JSON log không PII [S2][S19].
